# liquiforge 架构设计

## 一句话

一个 **tri-hybrid 混合骨干**（线性注意力 + 深度卷积 + 稀疏 MoE）吃下五种模态
（文本 / 视觉 / 音频 / omni / 决策），每种模态只靠一个轻量任务头 + 低秩适配器
从一个 Base 微调出来——这是 LFM3「一个骨干出六款模型」的零依赖参考实现。

## 分层视图

```
            ┌──────────────────────────────────────────────┐
            │              OmniBackbone（共享主干）          │
            │  embed → [TriHybridBlock] × N → RMSNorm       │
            │           ┌─────────────────────────┐         │
            │           │ LinearAttention (全局)   │         │
            │  block =  │ DepthwiseConv  (局部)    │ + gate  │
            │           │ SparseMoE      (容量)    │         │
            │           └─────────────────────────┘         │
            └──────────────────────────────────────────────┘
                 ▲           ▲          ▲          ▲
              TextHead   VisionHead  AudioHead  DecisionHead
              (LM)        (分类)     (转写)      (策略)
                              └──── OmniHead（跨模态检索）────┘
```

## tri-hybrid 为什么是「三合一」

1. **线性注意力**：softmax 注意力是 O(n²)；用正特征映射 φ(x)=ELU(x)+1 把
   `softmax(QKᵀ)V` 改写成递推 `S ← S + φ(k)vᵀ`，每次只做 O(d²)，序列越长越省。
   它负责**全局依赖**。
2. **深度卷积**：线性注意力对「局部邻域」的归纳偏置弱，补一个因果深度卷积，
   只回看过去 kernel 个位置，负责**局部结构**。
3. **稀疏 MoE**：参数量想做大、又想推理便宜，就 top-k 路由——每 token 只跑 k 个
   专家，容量随专家数涨、算力不涨。负责**容量**。

三者并联 + 可学习门控再残差相加，就是 tri-hybrid block。

## 一个 Base 出五款模型的关键

- **统一 token 空间**：每个 token 是 `(modality, local_id)`，映射到同一张嵌入表
  的相邻区段；模态间共享 embedding，是跨模态对齐的物理基础。
- **共享主干 + 轻头**：主干权重完全复用，文本/视觉/音频/决策各自只换一个线性
  头；omni 头则学一个共享投影空间做跨模态检索。
- **LoRA 微调**：冻结主干，只训 `A@B` 低秩残差（rank≈8），每个变体的增量参数
  只占全量的零头，存储/迁移成本降到最低。
- **决策 RL**：决策头用 REINFORCE 风格策略梯度，配确定性奖励 oracle，可端到端
  验证。

## 可证伪性（这是参考实现的核心价值）

每个指标都从一个真实前向传播算出来，且随 `skill` 单调变化：

| 模态 | 指标 | 方向 |
|------|------|------|
| 文本 | perplexity | ↓ |
| 视觉 | accuracy | ↑ |
| 音频 | WER | ↓ |
| omni | recall@1 | ↑ |
| 决策 | success rate | ↑ |

skill=0.5 是纯随机基线，skill→1 是 oracle 主导；boost=(skill−0.5)×2。
