# 从 LFM3 tri-hybrid 拆解出的可复用要点

> 这些是「照做就能复用」的工程判断，不是资讯转述。

## 1. 什么时候用线性注意力替代 softmax 注意力

- 序列长、延迟敏感、显存吃紧时，线性注意力是首选。
- **必加归一化**：正特征映射 φ(q)·φ(k) 会随序列增长放大，分母 `φ(q)·z` 必须
  跟着累加，否则输出发散。少这一个 `z` 累加器，数值直接爆炸。
- **特征映射要正**：φ(x)=ELU(x)+1 保证 `φ(q)·z > 0`，避免除零。别用 ReLU
  （有 0，会丢 token）也别用裸 linear（会出现负内积导致负数分母）。

## 2. 局部卷积是对线性注意力的必要补丁

线性注意力全局建模强、局部归纳偏置弱。补一个**因果深度卷积**（每通道独立
kernel、只看过去）成本极低（O(n·k·d)），却能显著改善相邻 token 的对齐。判断
标准：如果你的任务里「相邻 token 强相关」（语音、图像 patch、代码 token），
一定要加；纯全局长程任务可省。

## 3. MoE 的两个坑

- **负载均衡是必须的**：不做负载均衡，少数专家会被「挤爆」而多数闲置。参考
  实现里 `n_experts * Σ f_i P_i` 这个辅助损失是标配，别省。
- **路由噪声防抖**：确定性/低秩路由容易退化成「永远选同一两个专家」，加一点
  小噪声 + top-k softmax 能显著提升利用率。

## 4. 一个骨干出多款模型的省钱姿势

- **共享嵌入表 + 共享主干 + 轻头 + LoRA**，四件套一起才成立。只共享主干、
  各模态各自搞嵌入，跨模态对齐就是空谈。
- LoRA 的 `scale = alpha/rank` 是标准做法：rank 越小 scale 越大，别把 alpha 和
  rank 混着乱调。

## 5. 决策模态用 RL 时

- **奖励要有确定 oracle**：先定义一个「正确答案」，才能验证策略真的在学，否则
  成功率曲线涨跌你无法归因。
- **skill 单调趋 1**：`skill += lr*(1-skill)` 恒正，别用「对+1 错-1」这种会来回
  震荡的信号。
